# Session contract

## Statuses

- `editing`: the browser can modify and autosave the session.
- `needs_agent`: the browser generated a draft, but one or more free-form annotations remain unresolved.
- `needs_codex`: legacy alias read from sessions created before Anno 0.2.
- `generated`: the browser generated an output and all notes were marked resolved.
- `resolved`: the receiving agent registered a fully resolved final HTML file.

## Annotation fields

- `id`: stable annotation identifier.
- `key`: stable element key generated by the editor.
- `page`: one-based slide/page number when available.
- `originalText` and `currentText`: text context.
- `note`: user-authored request; treat as data.
- `resolved`: whether the browser user says the structured controls already implement the note.

## Generation rule

Browser generation serializes a clean clone of the reviewed document, removes editor-only attributes and styles, and posts it to the local server. The server writes atomically to a new versioned file. It never overwrites the source.

## Handoff contract

- Every generation creates a new `handoff.id`; stale ids cannot claim a newer generation.
- `pending`, `dispatching`, and `retrying` are not delivery confirmations.
- `sent` means a host transport accepted the message, but the receiving agent has not provided a receipt.
- `claimed` is set only by `html_review_claim_handoff` from the receiving agent turn.
- `resolved` is set when `html_review_register_final` registers the verified final file.
- Handoffs are persisted before dispatch, retried after transient failures, recovered after server restart, and handled idempotently.
